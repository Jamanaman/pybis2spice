pybis2SPICE User Guide
######################

pybis2SPICE can be used either via the app or programmatically. 
The tkinter gui as shown below allows users to be able to browse through ibis files 
and select components and models to be able to generate SPICE subcircuit files for 
ngSPICE, LTSPICE or generic SPICE format (useful for older spice simulators or for simulators that still support Berkeley SPICE3f5).


.. image:: /user_guide_images/loaded_ibis_file.png

The basic workflow is as follows:

   1. Select .ibs file corresponding to the packaged component you wish to model.
   2. Select the specific component from the `IBIS Component Select` field This is usually a package variant or different options for a chip for example.
   3. Select the model from the `IBIS Model Select` field related to the pin of the component which you wish to connect to a SPICE simulation.  
   4. Configure the model for your specific simulation purposes. The corner selection allows one to choose different performance cases. Selecting all will generate identically configured SPICE models for all 3 corners.
   5. Generate the SPICE model. Here, if one is generating ngSPICE models, it is recommended to select the .lib file type as it works better for direct imports into ngSPICE simulations and for use as a SPICE library component in QUCS-S.

In addition to this one can check the selected model as shown in the below figures.  

.. image:: /user_guide_images/check_ibis_model.png
    :width: 70%
    :align: center

.. note::
    One can only check the features which are present naturally, so input models will lack any VT tables and terminations may only consist in package components.

After one has generated a model, one can directly apply them in the desired simulation environment. Some examples of this are given in the following sections. 
For detailed programming documentation, refer to the :doc:`/source/pybis2spice` API documentation.

Using pybis2SPICE models with SPICE applications
************************************************

===================

Once one has generated the needed models in .lib format and having selected the ngSPICE format, 
one can use the model within QUCS-S using the SPICE Library Component as shown below.

LTSPICE
=======

Another popular choice for simulating due to its ubiquitousness and availability of 
industry standard component models is LTSPICE. This can be used very directly
with the models generated by pybis2SPICE as it generates a .sym file formatted for
LTSPICE directly.

.. image:: /user_guide_images/lt_model.png
    :align: center
    :width: 30%

As in the above simulation in QUCS-S, this can be directly wired into normal simulations. 

Configuring models with predefined stimuli
==========================================

pybis2SPICE allows the user to select a predefined stimulus out of the following options:

  1. **OSC**: Continuously oscillating between HIGH and LOW, starting LOW
  2. **OSC_INV**: Continuously oscillating between HIGH and LOW, starting HIGH
  3. **HIGH**: Continuous logic HIGH
  4. **LOW**: Continuous logic LOW
  5. **RISE**: A single transition from LOW to HIGH
  6. **FALL**: A single transition from HIGH to LOW
  7. **RAND**: Pseudorandom Binary Sequence (PRBS7)
  8. **RAND_INV**: Inverted PRBS (PRBS7)
  9. **HIGH_Z**: High impedance state if the buffer can achieve this

**ALL**: Allows the user to select between the above without changing the model. Allows for parametrization of stimuli without having to generate your own PWL signals.

All stimuli which have a start time can be configured with a delay value in seconds as below. 
Oscillating and PRBS stimuli can be configured with a frequency as well and oscillating stimuli
can be configured with a duty cycle. When using a model generated with the ALL stimulus, the
unused parameters are ignored. The stimuli can be chosen using an ALL model by setting the stimulus 
parameter to the corresponding number of the stimulus as in the list above. In the image below, the 
model is configured for continuous oscillation at 10 MHz with a 50% duty cycle and no delay.

Programming with pybis2SPICE
****************************


pybis2SPICE also can be imported directly as a python package. For this purpose one can simply
``pip install pybis2spice`` and import it as any other package. pybis2spice is composed of a number 
of submodules. One of the most useful modules for direct use is the ``pybis2spice.circuit_builder`` module 
which provides a function for generating a SPICE subcircuit card configured as in the GUI examples.
Apart from this ``pybis2spice.data_model`` provides a lot of features to be able to read IBIS files and make 
changes to IBIS files to then customise them in the form of ``DataModel`` objects. These can then be 

.. note:: 
    There is currently no support for writing IBIS models from this package, however, one can save DataModels
    through pickling for reusability. 

Generating models using pybis2spice.circuit_builder and DataModel
=================================================================


Below is an example of using the ``DataModel`` class and ``generate_spice_model_file`` function
to generate an IBIS model from an IBIS file and package it into a custom class. This example snippet comes from 
prerelease source code from (https://github.com/Jamanaman/SINGr.git). ::

    from pybis2spice import subcircuit as sckt, circuit_builder as ckt_build, data_model as dm

    class IBISModel(Model):  
    @classmethod
    def build_model_from_file(
        cls, model_name:str, component_name: str, 
        ibis_file:str, io_type:sckt._IO_TYPE, corner:sckt._CORNER, 
        stimulus:Optional[sckt._STIMULUS]='ALL', lib_path:Path|str = '.'
        ) -> Model:

        if stimulus == 'ALL' or stimulus is None: 
            spice_model_name = f'{model_name}_{io_type}_{corner}'
            subcircuit_card_path = Path(lib_path, f'{model_name}_{component_name}_{corner}_{io_type}.lib')
        else:
            spice_model_name = f'{model_name}_{io_type}_{corner}_{stimulus}'
            subcircuit_card_path = Path(lib_path, f'{model_name}_{component_name}_{corner}_{io_type}_{stimulus}.lib')
        if subcircuit_card_path.name in os.listdir(Path(lib_path)):
            spice_str = open(subcircuit_card_path, 'r').read()
            return IBISModel(model_name=model_name, component_name=component_name, subcircuit_card=spice_str, lib=subcircuit_card_path, spice_model_name=spice_model_name)
        try:
            ibis = ecd.load_file(Path(lib_path) / ibis_file, transform=True)
        except FileNotFoundError as e:
            e.add_note(f"IBIS Model file: {ibis_file} not found.")
            raise e

        model = dm.DataModel(ibis_file=ibis, model_name=model_name, component_name=component_name)
        if stimulus == 'ALL':
            subcircuit_card_path = Path(lib_path, f'{model_name}_{component_name}_{corner}_{io_type}.lib')
        else:
            subcircuit_card_path = Path(lib_path, f'{model_name}_{component_name}_{corner}_{io_type}_{stimulus}.lib')
        spice_str = ckt_build.generate_spice_model_file(io_type, 'ngSPICE', model, corner, truncation=0.01, stimulus=stimulus, output_filepath=subcircuit_card_path)

        return IBISModel(model_name=model.model_name, component_name=component_name, subcircuit_card=spice_str, lib=subcircuit_card_path)

Using InSPICE to import generated models into ngSPICE in python
===============================================================

To be able to easily parametrise simulations across a broad range of different 
features, one can use something like InSpice_ as shown below to be able to include
the generated models. Note this can be done also by using the GUI to be able to 
first generate ngSPICE compatible *.lib* files and then placing these into a directory
where one can simply include the file using the include statements accessed as below using 
``circ.include``.

.. _InSpice: https://github.com/insim-ai/InSpice.git

::

    freq = 10e6
    circ = Circuit('P2P')
    circ.include(sender_1.lib) # include .lib files
    circ.include(receiver_1.lib)
    circ.X('sender1', sender_1.spice_model_name, 'node_out', 'node_stimulus_in')
    pwl_vals = make_pwl_from_bitstream(randint(2, size=128), period) # PRBS7 bitstream
    circ.PieceWiseLinearVoltageSource(
        'pwl', 'node_stimulus_in', circ.gnd, 
        pwl_vals, repeat_time=0, delay_time=1/freq)

    ## RC Transmission line segment
    circ.R('R1', 'node_out', 'node_r_out', 100) # 100 Ohm in series
    circ.C('C1', 'node_r_out', circ.gnd, 10e-6) # 10 pF to ground

    ## Receiver subcircuit
    circ.X('receiver1', receiver_1.spice_model_name, 'node_r_out')
    simulator = Simulator.factory()
    simulation = simulator.simulation(circ)
    results: TransientAnalysis  = simulation.transient(step_time=(1/freq)/100, end_time=(128+1)/freq, max_time=max_step_s)
